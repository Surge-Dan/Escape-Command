# 微逃顶部规范 + 破圈路由修复

## Context（为什么做这个改动）

用户复盘《演示录屏》后提出 3 个问题：

1. **微逃骰子页面与 chenhao 分支设计差异过大**：当前 `dice-micro-7d` / `dice-result-7d` 的 WXML/WXSS 虽是 chenhao 分支原版，但用了深蓝 `#1a1f2e`/`#2d3548` 配色（与 Daniel 暖棕品牌色不符），且无统一顶部导航头。
2. **微逃各页面顶部未遵循规范**：缺标题+分隔线，内容贴顶，未避让右上角胶囊按钮。
3. **破圈骰子异常**：证书页 `bt-certificate` 文件经核实**完整存在**（4 文件齐全），破圈模块文件自 `c7ed207` 起未被动过。真正问题是**路由 bug**：首次点击破圈骰子走 `generating?mode=breakthrough`，但 `generating.js` 用 `generatorEngine.generate(ctx)` 从**普通 commandPool** 生成指令（非 breakthrough 类型）→ `executing` 页 `isBreakthrough=false` → 完成后 `record.goNext` 走 map，**到不了证书页**。同时首页新增的"出逃记录"板块渲染旧存储记录时出现 `null分钟`（旧记录 duration 缺失）。

经用户确认：① 微逃两页保留 chenhao 布局 + 新增 nav-header + 换暖棕配色；② 破圈路由按"修复路由"方案处理。

## 改动二：破圈骰子路由修复（`pages/generating/generating.js`）

让 `mode==='breakthrough'` 走破圈专属池 `app.rollBreakthroughCommand()`（用 `breakthroughPool`），而非 `generatorEngine.generate`（普通池）。保留骰子动画。

- **`onLoad`**：在设置 `requestMode` 后，若为 `breakthrough` 且 `app.globalData.breakthroughReRollCount <= 0`，`wx.showToast` 提示"今日破圈次数已用完，明天再来"并 `navigateBack`，不启动动画。
- **`_generateAsync(ctx)`**：新增 breakthrough 分支——
  ```js
  if (this.data.requestMode === 'breakthrough') {
    const cmd = app.rollBreakthroughCommand ? app.rollBreakthroughCommand() : null
    if (cmd) {
      if (app.useBreakthroughReroll) app.useBreakthroughReroll()  // 消耗1次，与首页重摇一致
      this._generatedCommand = cmd
      this._generatedFallback = false
    } else {
      this._generatedCommand = null
    }
  } else {
    // 原有 generatorEngine.generate(ctx) 逻辑保持不变
  }
  ```
- **`_advance`**：无需改。breakthrough 指令不在 `commandPool`，`poolCmd` 为 undefined，`normalizeCommand(poolCmd||cmd)` 仍得到 `type:'breakthrough'` 的指令 → executing `isBreakthrough=true` → record.goNext → bt-certificate。
- loading 文案：`getLoadingCopy(ctx)` 已支持 `mode:'breakthrough'`，无需改。

> 说明：此为 bug 修复，不改破圈功能设计/数据/证书页本身。`rollBreakthroughCommand` 返回的指令已带 `duration`（5-40），不会再产生 null。

## 改动三：首页 null分钟 防御（`pages/index/index.js` + `index.wxml`）

`record-builder.buildRecord` 对新记录恒产出数字 duration，`null分钟` 来自旧存储记录的缺失字段。在展示层兜底：

- **`decorateRecord(r)`**（index.js）：返回对象里追加 `duration: (typeof r.duration === 'number' && r.duration > 0) ? r.duration : 0`，杜绝 null/undefined 透传。
- **`index.wxml`**：last-record-card 与 recent-card 的 `{{...duration}}分钟` 改为 `{{...duration || 0}}分钟`（0 比 null 友好；后续新记录均为有效值）。

不动 `normalizeCommand`/`record-builder`（避免影响破圈/普通指令评分逻辑，尊重"模块不大改"）。

## 不做的事（核对用户原话）
- 不改破圈模块文件（`executing.js` / `bt-certificate.*` / `breakthrough-commands.js` / `app.rollBreakthroughCommand`）——已确认自 `c7ed207` 未变。
- 不删首页"出逃记录"板块（用户说"历史记录暂时保留"）。
- 证书页文件已存在，无需重建。

## 验证
1. **微逃**：开发者工具进首页→微逃骰子→条件页：顶部应有"微逃骰子"标题+分隔线、不贴顶、避让胶囊；配色为暖棕（非深蓝）。选条件摇骰→结果页：同样顶部规范；接受指令→executing 正常。
2. **破圈**：首页→破圈骰子→generating 骰子动画→落定→executing 应显示破圈 UI（勇气计/破圈贴士，`isBreakthrough=true`）；4 步完成→record→"我破圈了"→bt-certificate 证书页可见。重摇仍走 `rollBreakthroughCommand`。次数耗尽时提示且不进入 generating。
3. **null分钟**：清缓存后新走一遍流程，首页"上次/最近出逃"卡片时长显示数字（无 null）；旧脏数据降级为 0。
4. **回归**：`node tests/run-all.js` 全套件通过；确认未误伤微逃/破圈/同频既有测试。
